## How Turnkey works

The core Turnkey primitives are: organizations (including sub-organizations), users, policies, and wallets.

<Frame>
  <img src="/images/concepts/all_concepts.png" alt="all concepts screenshot" />
</Frame>

- **Organizations (parent orgs)** are top-level entities that contain users, wallets, and policies. The initial parent organization typically represents an entire Turnkey-powered application.
- Parent organizations create **sub-organizations (sub-orgs)**: fully segregated organizations nested under the parent. Parent orgs cannot modify the contents of a sub-org. Sub-orgs typically represent an end user.
- **Policies** govern what activities are allowed, like signing transactions or creating users.
- **Wallets** are HD seed phrases that can generate multiple wallet accounts--also known as _addresses_--for signing operations.

<Tip>
This structure enables an important security approach: private keys are never directly managed; keys are stored in wallets accessed through authenticators like passkeys, social logins, or API keys.
</Tip>

## Manage interactions and organizations

There are two primary ways to interact with Turnkey: the Turnkey Dashboard and the API.

The Turnkey Dashboard is where you create your Turnkey parent organization. Root users of your parent organization also typically manage administrative activities in the Dashboard. The Dashboard only supports passkey authentication.

Interactions with Turnkey at scale (primarily, interactions initiated by end users) are performed programmatically by calling the Turnkey API. The API supports a variety of authentication methods.
