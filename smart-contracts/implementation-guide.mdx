This guide walks through a complete setup for managing smart contracts with Turnkey. By the end, you will have an organization with defined users, dedicated signing wallets, proper authentication, and policies that enforce exactly who can interact with your contracts.

## Prerequisites

- A [Turnkey account](https://app.turnkey.com/dashboard/auth/initial) with an organization created
- The [`@turnkey/sdk-server`](https://www.npmjs.com/package/@turnkey/sdk-server) package installed
- An API key pair for your root user (generated during onboarding)

## Architecture overview

A typical smart contract management setup looks like this:

| Component | Purpose |
| --- | --- |
| **Organization** | The top-level container for all resources |
| **Users** | Human operators and machine accounts with tagged roles |
| **Wallets** | HD wallets that hold the keys used for contract deployment and interaction |
| **Authenticators** | API keys (for machines) and passkeys (for humans) that prove identity |
| **Policies** | Rules that govern which users can sign which transactions |

## Example: Stablecoin management

Consider a stablecoin contract where you need:

- A **deployer** who can publish the contract
- A **minter** who can issue new tokens, with amount limits
- An **upgrade owner** who can upgrade the implementation, only when explicitly authorized

With Turnkey, each role maps to a user with a dedicated wallet and a scoped policy:

```
Deployer user  →  deployer-wallet  →  policy: allow deploy to chain 1
Minter user    →  minter-wallet    →  policy: allow mint() up to 1M tokens
Upgrade owner  →  upgrade-wallet   →  policy: allow upgrade() (temporary, revoked after use)
```

This "Security as Code" approach ensures that every contract interaction is explicitly authorized, auditable, and enforced by Turnkey's infrastructure.

For a working implementation, see the [Smart Contract Management demo on GitHub](https://github.com/tkhq/solutions/tree/main/smart-contract-mgmt).
